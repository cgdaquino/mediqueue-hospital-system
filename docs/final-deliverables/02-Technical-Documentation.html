Hospital Appointment and Queue Management System
CS0053 / November 24 2026

MediQueue implements the Appointment Scheduling System option in the supplied CS0053 brief. The local system coordinates patient bookings, doctor availability and queue views, and admin oversight through Flask and SQLite.

Architecture and domain concepts

Request flow: browser interface -> Flask route and role/CSRF guard -> scheduling or registration rules -> SQLAlchemy models -> SQLite. Scoped JSON responses feed the role-specific browser scripts. Presentation lives in templates/static files; reusable rules live in scheduling/registration helpers; models/migrations handle data storage.

This is a pragmatic layered design, not a strict dependency-inverted Clean Architecture. Routes still call SQLAlchemy and contain use-case logic. A repository/service abstraction is a future refactor, not a completed feature.

Domain driven design

EntityDomain meaning
UserPatient, doctor or admin account with enabled/auth version
DoctorClinician profile, department, active status and consultation duration
AppointmentOnline or walk-in booking, assigned doctor and clinical status
WeeklyAvailabilityWorking hours and optional lunch for a doctor/weekday
BlockedDateDoctor-specific unavailable date
ActionActor-owned short-lived undo snapshot

Ubiquitous vocabulary: Confirmed, Completed, No-show, Cancelled, consultation duration, working day, lunch break and patient-only removal. Patients own their bookings; doctors manage their schedules; admins coordinate hospital-wide activity.

Database relationships and invariants

Relationship or constraintPurpose
User.doctor_id unique -> Doctor.idAt most one login per doctor profile
Appointment.doctor_id -> Doctor.idEvery booking has a clinician
Appointment.patient_id -> User.id nullableOnline patient ownership; walk-ins may have no patient login
WeeklyAvailability doctor/weekday uniqueOne setting per doctor per weekday
BlockedDate doctor/date uniqueNo duplicate blocks
Occupied doctor/date/start unique indexNo duplicate occupied start; cancelled rows excluded
Interval checks under write lockReject partial overlaps as well as equal starts
Action versioned snapshotsUndo cannot overwrite intervening changes

Appointments snapshot consultation duration; changing doctor settings never resizes old bookings. ISO date/time strings use hospital-local time consistently. Overnight shifts are rejected. SQLite BEGIN IMMEDIATE serializes competing booking/block/settings/account writes. Booking rechecks active status inside that lock.

Cancellation releases an interval but preserves staff records. Patient-only removal changes a visibility flag. The migration adds missing columns without deleting records; legacy doctor retirement occurs only during the relevant initial upgrade, so later admin activation survives restart. The upgrade path is SQLite-specific, not a general migration framework.

API authentication and read operations

GET /login or /register establishes a session and CSRF token. Submit the HTML form with csrf_token. Login rotates the session. JSON writes need the current X-CSRF-Token and session cookie. Read the hidden login token or csrf-token dashboard meta tag; Postman must retain cookies.

HTTP outcomes: 200 successful read/update, 201 created, 400 invalid input or CSRF, 401 missing/invalidated session, 403 forbidden role/record, 404 missing record, 409 schedule, state or undo conflict.

Each weekly object contains weekday (0 Monday through 6 Sunday), enabled, start, end, lunch_start and lunch_end. Use null for both lunch times to disable lunch. Read existing days first, then send all seven complete objects. The Postman collection follows this pattern.

Session cookies use HttpOnly and SameSite Lax. This local instance uses HTTP. Production HTTPS, secure cookie configuration, rate limiting, backups and a production web server remain deployment work. Use fictional information in the class demonstration.

Doctor calendar and admin records poll every ten seconds while visible and refresh on focus. Patient pages load on opening/reload and after their own actions. Reload a patient page to see newly created doctors or changes from staff.
