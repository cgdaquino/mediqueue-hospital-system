Installation and startup

1. Install Python 3.11 or newer. Use Node.js 18 or newer for interface tests. Extract the source and open mediqueue-hospital-system.

2. Create a virtual environment, install requirements, and run seed-demo. Choose a private password. Existing accounts are retained.

3. Run python run.py. Open http://127.0.0.1:5000. The current authoring preview uses port 5055.

python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m flask --app run seed-demo
python run.py

Use the password chosen during setup. Public registration creates patients only. Admins create doctor accounts. There is no public administrator registration or password-recovery email workflow. Tabs share sign-in cookies; use separate browser profiles/private sessions for simultaneous role views.

Patient booking

Figure 2. Doctor selection and consultation time ranges.

1. Register a patient account or sign in. Select a department and active doctor. Admins may add more doctors to the initial three-person roster.

2. Choose a future date. Blocked/non-working dates show a red warning below the field. Working dates show clinic and lunch hours.

3. Choose an available start/end range and Confirm Appointment. The doctor sets consultation length. Past times, occupied intervals, lunch and closing overflow are excluded.

4. Review My Appointments. If someone takes the slot first or the schedule changes, choose a refreshed range.

Patient history and undo

1. Cancel your own future confirmed booking to release its interval.

2. For a cancelled entry, choose Remove from my list to hide it only from your patient view. Staff history and CSV records remain.

3. Use the bottom-right Undo within five seconds when offered. The server refuses expired tokens, changed records or unavailable slots.

Patients cannot mark Completed or No-show. The assigned doctor or admin records completion after the appointment ends, or no-show after it starts. Reload the patient screen to see another role’s changes.

Doctor availability

Figure 3. Weekly hours, lunch and duration controls.

1. Sign in with the doctor account supplied by an admin. Expand Weekly availability and lunch break.

2. Set working days, start/finish and optional lunch. Times use 15-minute increments. Overnight shifts are unsupported.

3. Choose 15, 30, 45, 60, 90 or 120 minutes and Save availability. Existing appointments retain their original duration. Resolve future confirmed conflicts before closing their day/time.

4. For a single day off, use Block an Unavailable Date. Confirmed bookings must be resolved first. Unblock restores that date.

Doctor calendar and queue

Figure 4. Online bookings and walk-ins share the doctor calendar.

Use Calendar or Queue, select the correct date, and navigate with Week/Day, arrows, Today or the date picker. Calendar events open details and the same eligible status actions as Queue.

Complete after the end; record No-show after the start. Cancelled bookings remain grey/dashed history. Counters refer to the selected day; the calendar footer counts its displayed period. Data refreshes every ten seconds while visible, on focus, or with Refresh.

Only the seeded demo doctor can switch POV. Ordinary doctor accounts remain assigned to their own profile. Stale POV tabs reload or reject changes.

Admin appointments

Figure 5. Hospital records, search, filters and status actions.

1. Search by patient, doctor or reference. Filter by status and sort by patient, doctor or date. Filters remain during refresh.

2. Register a walk-in with a patient name, doctor, future date and available range. It follows the same schedule rules as online booking.

3. Record eligible outcomes or cancellation. Export CSV downloads all hospital records, regardless of the current search filters.

The admin table checks for changes every ten seconds while visible. Patient removal does not remove the hospital record.

Admin doctor accounts

Figure 6. Admin-only doctor account controls.

1. Expand Doctor accounts. Select a new profile or an existing profile without a login.

2. Enter name, supported department, unique email and an initial 8–128-character password. Create the account and share credentials privately.

3. Use Edit account for details or a new password. Leave password blank to retain it. Changes sign the doctor out of existing sessions.

4. Deactivate to prevent sign-in and new bookings. Existing appointments stay saved for review; resolve them as necessary. Reactivate to restore access.

A department change is refused while future confirmed bookings exist. Passwords are hashed and never displayed after saving.

Troubleshooting and data care

ProblemResolution
Address does not openStart Flask and use its displayed port.
Dashboard styling absentCheck internet access for the Tailwind CDN.
New doctor missingConfirm active status/department, then reload patient page.
Calendar record missingCheck doctor assignment and selected date/week; Refresh.
Seeded profile cannot sign inAdmin must create its login; a doctor profile alone is not an account.

SQLite data and the session secret live in instance/. Back up that folder before migrating or moving an existing installation. The source archive excludes instance/, credentials and the virtual environment. A fresh installation requires setup and starts with fresh data.

Use fictional data for presentations. This local class project does not provide clinical records, billing, email/SMS, password recovery or production hosting configuration.
