Reproducing the completed Postman run

1. Create a disposable local installation, seed demo accounts with a private password, and start it on port 5000.

2. Import API/MediQueue.postman_collection.json and MediQueue.postman_environment.json. Select the environment.

3. Set password to your chosen demo password and booking_date to a future Monday–Friday. The collection handles CSRF tokens and cookies.

4. Run all 33 requests in order. It creates a unique test doctor, saves hours, books, rejects duplicates, verifies scope, cancels/removes and checks retained history.

5. Capture the actual runner summary, GET appointments 200, POST booking 201, PUT hours 200, DELETE removal 200, duplicate booking 409 and forbidden role 403 with test results.

6. Export actual runner results into Testing/ and save screenshots in Screenshots/Postman/. Remove passwords from saved environment values and screenshots. Record any failure honestly.

The collection leaves its doctor inactive and retains cancelled records. Direct HTTP evidence is supplementary and does not replace the required Postman step. No screenshot is presented as Postman when it came from a different tool.
